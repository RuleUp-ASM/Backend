# 비동기 작업 롤백·재시도 (APL-04 / SAN-09 조사)

2026-09-18 스테이징에서 `SCORE_INPUT` 한 건이 `ck_score_balance` 제약을 위반했다.
해당 QA 계정의 현재 점수는 10, 원장 `SUM(applied_delta)`는 17로 불일치했다.
점수나 원장을 직접 덮어쓰는 시드는 정상 점수 정정 테스트의 전제가 될 수 없다.
제약을 제거하거나 원장을 임의로 다시 쓰지 않는다.

스케줄러는 실행 중이었지만, 핸들러 실패로 rollback-only가 된 트랜잭션 안에서
재시도 횟수도 함께 저장했다. 커밋 때 모두 롤백되어 DB의 attempts는 계속 0이었고,
예외가 배치 바깥으로 전파되어 뒤의 정상 작업도 처리되지 않았다.

핸들러 변경과 processed_at은 한 트랜잭션으로 유지한다. 그 트랜잭션이 실패하면
롤백을 완료한 뒤 별도 트랜잭션에서 attempts·백오프·last_error를 저장하고 다음
메시지를 처리한다. 잠금을 얻은 뒤 available_at을 다시 확인하므로 오래된 due 목록이나
경합한 소비자가 백오프를 건너뛰지 못한다. 5회 실패하면 dead-letter로 남는다.

`OutboxRollbackIT`는 실제 트랜잭션 핸들러의 부분 쓰기 롤백, 실패 기록 존속,
후속 정상 메시지 처리, 백오프, 5회 실패 상한을 MySQL에서 검증한다.

배포 후에는 적체 메시지의 attempts와 processed_at, dead-letter 목록을 확인한다.
원장 불일치 계정은 기존 원장과 QA 시드 이력을 대조해 별도로 복구해야 한다.
실패 계정의 점수를 자동으로 0이나 임의 값으로 맞추는 조치는 포함하지 않는다.
