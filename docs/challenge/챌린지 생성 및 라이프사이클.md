# 챌린지 생성 및 라이프사이클

기준: [공통 테크스펙](https://app.notion.com/p/3aaad4145fb680e59927e688ed8d0594),
[백엔드 상세](https://app.notion.com/p/3aaad4145fb68095803de5fec95e9325), 2026-09-15 정합화.

## 문서 충돌의 적용 기준

- 정원은 사용자 확인(2026-09-15)에 따라 **5·30·100·300 중 하나 또는 무제한(null)**이다. 자유 입력이 아니므로 범위 안이라도 선택지 밖 값(47·50 등)은 400 `CAPACITY_OUT_OF_RANGE`다. 초안 기본값은 **30**이고(옛 기본값 50 은 선택지가 아니라 그대로 두면 초안 확정이 400 이 된다), 10,000명 제한은 쓰지 않는다. SOLO는 정원 1로 정규화한다. 생성과 수정이 같은 집합을 쓴다.
- minTier는 생성자 표시 티어 이하여야 하며, 생성 후에는 시작 전 + 방장 혼자일 때 수정할 수 있다.
- SQS에는 `challengeId`와 `targets`만 싣는다. 콘텐츠는 소비 시 DB에서 읽으며, 운영 로그에는 원문을 기록하지 않는다.
- 프론트 계약의 `IN_REVIEW`는 공통 문서의 `PENDING`, `NONE`은 `NOT_REQUIRED`에 해당한다. 기존 API/DB 이름은 유지한다.
- 공유 moderation revision을 추가하지 않는다. 필드별 콘텐츠 대조로 오래된 결과를 거른다.

## 생성과 초안

경로 A는 루틴 카탈로그의 템플릿을 사용하고 LLM을 호출하지 않는다. 경로 B는 사용자별 분당 10회 제한 후 LLM 초안을 만든다.
Redis 키는 `rate:challenge:draft:{userId}`이며 Lua 한 번으로 INCR, 최초 EXPIRE 60, TTL 조회를 처리한다.
Redis 장애 시 Caffeine 제한기로 전환하고 `challenge.draft.rate_limiter.fallback`과 구조화 로그로 기록한다.

LLM 차단·장애·파싱 실패·제목 누락은 FALLBACK 응답이며 draftId를 발급하지 않는다.
사용자 원문을 누락된 AI 제목/설명 대신 복사해 심사를 면제하지 않는다.
정상 초안은 24시간 보관하고 생성 시 본인 소유·만료 여부를 검사한다.
AI 제목과 출처(origin/sourceChallengeId)는 서버가 초안에서 복사한다.

생성의 Idempotency-Key는 DB 키 행을 선점하고 잠금 안에서 요청 해시를 비교한다.
동일 키·동일 본문은 최초 응답을 재사용하며 다른 본문이면 충돌한다.
카테고리는 초안과 동일해야 하며 인증 방식은 AUTO → MANUAL만 허용한다.
종료일 null은 무기한이다. 시작일은 KST 날짜를 기준으로 검증한다.

## 설정과 가입

- 시작 전 + 방장 혼자: 카테고리를 제외한 설정 변경 가능.
- 시작 후 또는 타인 참여: 제목·설명·이미지·정원만 변경 가능.
- mode·capacity·visibility·rankingVisible은 최종 모드를 기준으로 적용한다.
- 현재 인원보다 작은 정원은 거절한다. 판단은 ACTIVE 멤버 행을 직접 센다.
- 점수/공유 패널티 응답은 인증 방식/모드에서 파생하며 watcher만 선택값이다.
- 설정 변경·가입·탈퇴·강퇴는 settings version을 갱신한다.
- 무제한 방도 version 갱신을 위해 처음부터 방 쓰기 잠금을 잡는다. 공유 잠금에서 쓰기 잠금으로 승격하는 경합을 피하기 위한 선택이다. 정원 COUNT는 유한 정원 방에서만 실행한다.
- 가입 거절은 409 JOIN_BLOCKED와 reason으로 통일한다. 비공개 초대, PERMANENT_BAN, 재입장 대기, 정원, 표시 티어 순으로 판정한다.
- 기기 권한은 가입 서버 게이트가 아니다. 공개 상세의 requiredPermissions를 보고 클라이언트가 확보한다.
- 방장 식별 원본은 owner_id다. Phase 1의 owner 변경은 이탈 시 BOT 전환이며 DB CHECK로 owner_id/owner_type 조합을 강제한다.

## 사후 심사

제목·설명은 초안 원본과 동일하면 EXEMPT, 설명이 없으면 NONE, 변경된 값은 IN_REVIEW다.
이미지 업로드는 IN_REVIEW이며, 미첨부/삭제는 NONE이다.
현재 PENDING인 전체 필드가 발행 대상이다. 거부 횟수만으로 수정을 잠그지 않는다.

생성·수정 트랜잭션에서 moderation_pending_since와 moderation_enqueued_at을 갱신하고 커밋 후 SQS에 보낸다.
발행 성공 시에만 moderation_enqueued_at을 기록한다. 발행 중 콘텐츠가 변경되면 성공 표시를 남기지 않는다.
소비자는 외부 심사 동안 DB 트랜잭션/행 잠금을 유지하지 않는다.
결과는 `BINARY field <=> BINARY reviewedValue AND status='IN_REVIEW'` 조건으로 필드별 반영한다.
실제로 갱신된 거부 결과에만 알림을 발행한다. 이미지 원본은 이의 근거로 보존하고 공개 응답에서 가린다.

5분마다 발행 미확인 상태로 10분 이상 대기한 방을 재발행한다.
소비 실패는 메시지를 삭제하지 않아 SQS visibility timeout/재전달/DLQ가 처리한다.
이미 종결된 필드의 중복 메시지는 상태나 알림을 바꾸지 않는다.

### 배포 설정

- `MODERATION_QUEUE_URL`: 챌린지 사후 심사용 SQS Standard 큐 URL. 알림 푸시 큐와 별도다.
- `AWS_REGION`: 기본 ap-northeast-2. 운영 자격증명은 기본 AWS provider chain을 사용한다.
- 큐에 DLQ redrive policy를 연결하고 DLQ 메시지 수와 발행 실패 로그를 경보에 연결한다.
- 소비 visibility timeout은 120초, SQS 호출 timeout은 10초다.
- `MODERATION_LOCAL=true`: 로컬/테스트에서만 인프로세스 심사를 사용한다. 테스트 프로필에 명시돼 있다.
- 큐 미설정 시 전송 실패를 기록하고 PENDING을 보존한다. 운영 배포에는 큐 설정이 필요하다.

## 이탈과 점수

자진 탈퇴는 1주 대기, 부정행위 강퇴는 해당 방 영구 차단이다.
계정 제재에 따른 자동 이탈은 SANCTION 사유를 보존하며 감점과 백오프가 없다.
탈퇴 감점은 멤버십 변경과 같은 트랜잭션의 outbox에 확정 사건을 기록하고, 별도 소비 트랜잭션에서 적용한다.
재입장 후 다시 탈퇴한 사건은 이전 탈퇴와 다른 sourceId를 사용한다.
수동 방에는 일일/마감/사건성 점수를 적용하지 않는다.

## 종료와 보존

활성화는 00:05 KST, 자동 삭제는 04:10 KST에 실행한다.
만료 방은 마지막 인증일의 유예 이후에 삭제 후보가 되며 유령방은 ACTIVE 멤버 0명으로 판정한다.
각 방의 잠금을 잡은 뒤 조건을 다시 확인한다. 후보 추출 후 새 멤버가 들어온 방을 삭제하지 않는다.
심사 PENDING, 미확정 판정, 미마감 점수 사이클이 있으면 삭제를 보류한다.
관리자 폐쇄는 close_reason=ADMIN으로 기록하며 미처리 작업이 있으면 일 배치가 이어 처리한다.

삭제 직전에 다음 데이터를 같은 트랜잭션으로 보존한다.

1. challenge_history: 공개 표시용 제목·설명·이미지, AI 제목, 방장, 모드/공개범위, 정원/티어/주간횟수, 기간, 인증 설정/목표값, 출처, 종료 사유.
2. challenge_member_history: 가입/실제 이탈 시각, 사유, 멤버 ID, 인증 입력 스냅샷, 최종 성공률.
3. challenge_final_ranking: 성공률·성공 횟수를 기준으로 산정한 최종 순위. 10회 미만은 미등재.

원본 판정·인증 설정 이력·이의·점수 원장·사이클·연속 상태는 보존하고 운영 방/멤버를 삭제한다.
점수 모듈은 동일 UUID의 이력에서 시작일·주간 목표·자동 인증 여부를 읽어 삭제 후 정정할 수 있다.
완료 목록·상세·최종 랭킹은 이력으로 조회한다. 사전 삭제된 구 이력의 누락 필드는 복원하지 않는다.
삭제 성공 로그와 탐색 인덱스 제거는 커밋 후 실행한다.

## 마이그레이션

V56은 신규 필드와 이력을 확장하고 verification_setting_snapshots의 운영 멤버 FK를 제거한다.
